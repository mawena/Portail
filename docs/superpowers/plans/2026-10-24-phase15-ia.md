# Portail — Phase 15 : intégration IA (serveurs auto-hébergés, chat, automatisations) — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Portail se connecte à un ou plusieurs serveurs IA auto-hébergés (VPS, machines locales) qui parlent un
contrat compatible OpenAI (le futur serveur maison, mais aussi Ollama, vLLM, LocalAI), pour discuter avec un modèle
(réponses en flux, Markdown, historique local) et lancer des automatisations réutilisables, à la demande ou planifiées.
Fin de phase : version **v1.8.0**.

**Architecture :**
- **Kotlin, paquet `com.mawena.fluluks.ai`** : interface `AiProvider` (santé, modèles, chat en flux, embeddings) et
  une première implémentation `OpenAiCompatibleProvider` sur OkHttp ; un lecteur SSE (`SseReader`) indépendant du
  transport ; `AiServers` garde les fournisseurs (JSON, clé API scellée par `SecretBox` comme les mots de passe de la
  phase 10) ; `ChatStore` (Room) garde conversations et messages ; `ChatSessions` tient les générations en cours et
  envoie les morceaux à Dart par Pigeon, avec acquittement (même mécanisme que la sortie des terminaux de la phase 13) ;
  `Automations` (Room + WorkManager) garde les tâches, leurs déclencheurs et leurs exécutions.
- **Flutter** : écrans Serveurs IA, Chat (liste des conversations, conversation), Automatisations ; un rendu Markdown
  maison sur le paquet `markdown` (analyse seulement), aux couleurs et typographies du design system de la phase 11.
- **Serveur de l'utilisateur : `https://atelier.mawena.cloud`** (son VPS, en service depuis le 2026-10-25, spec § 25 :
  `/health` → `{"status":"ok","version":"0.1.0"}`, `/v1/models` sans clé → 401 au format du contrat). Tout est
  codé contre le **contrat d'API** ci-dessous, vérifié contre ce serveur au début de la phase ; un **serveur d'essai**
  (`tools/ia/serveur-essai.py`, bibliothèque standard de Python) le joue pour le développement et les essais
  instrumentés, et `MockWebServer` (OkHttp) pour les tests unitaires.
- **Rien de secret dans les journaux** : ni clé API, ni contenu de conversation, ni prompt, ni réponse ; le journal de
  tentative (comme celui de la phase 13) ne garde que méthode, chemin, code HTTP, durées et tailles.

**Contrat d'API** (compatible OpenAI ; authentification `Authorization: Bearer <clé>` sur toutes les routes) :
- `GET /health` → `{ "status": "ok", "version": "…" }` ; *(décision du planificateur)* absent (404, cas d'Ollama),
  l'état se déduit de `GET /v1/models` ;
- `GET /v1/models` → `{ "object": "list", "data": [ { "id", "object": "model", "owned_by"? } ] }` ;
- `POST /v1/chat/completions` → corps `{ model, messages: [{ role: system|user|assistant, content }], stream,
  temperature?, max_tokens? }` ; `stream=false` : `{ choices: [{ message: { role, content }, finish_reason }], usage? }` ;
  `stream=true` : `text/event-stream`, lignes `data: {"choices":[{"delta":{"content":"…"},"finish_reason":null}]}`,
  fin par `data: [DONE]` ; une erreur en cours de flux arrive en `data: {"error":{"message":"…"}}` ;
- `POST /v1/embeddings` *(facultatif)* → `{ model, input }` → `{ data: [{ embedding: [..] }] }` : interface prévue
  dans `AiProvider`, sans écran en phase 15 ;
- erreurs : `{ "error": { "message", "type"?, "code"? } }` avec 400, 401, 403, 404, 429, 500, 503.

**Tech Stack :** Kotlin, coroutines (déjà présentes), **OkHttp 4.12.0** (nouvelle, Apache 2.0) et **MockWebServer
4.12.0** (tests), **Room 2.7** avec KSP (nouvelle, Apache 2.0), **WorkManager 2.10** (nouvelle, Apache 2.0), Pigeon
27.3.0, Flutter 3.41, paquet Dart **`markdown`** (nouveau, BSD-3, analyse seulement) ; JUnit 4, AndroidX Test.

**Spec :** [docs/superpowers/specs/2026-10-17-fluluks-design.md](../specs/2026-10-17-fluluks-design.md), **§ 23**
et **§ 24** et **§ 25** (numéro de phase, serveur de l'utilisateur).

- **Téléphone :** jamais de `flutter drive` sans `--keep-app-running`, jamais `connectedAndroidTest` ; essais

## Review Focus

1. **Flux coupé ou malformé** (ligne `data:` coupée entre deux paquets, `\r\n`, commentaires `:`, événement sans
   `choices`, JSON invalide, connexion fermée sans `[DONE]`) : le texte déjà reçu reste, la réponse est marquée
   interrompue avec un message français, jamais de plantage ni de texte dupliqué (`SseReader` T2).
2. **Arrêt d'une génération** pendant le flux, pendant la connexion, ou juste après `[DONE]` : la requête HTTP est
   annulée, la réponse partielle gardée et marquée « Arrêtée », aucun morceau tardif n'arrive ensuite à Dart (T6).
3. **401 / 403 / 429 / 5xx / délai / serveur injoignable / certificat refusé** : chacun a son message et son action
   (« Vérifiez la clé API », « Réessayez plus tard »…) ; un 401 ne relance jamais la requête en boucle (T2, T4).
4. **Clé ou contenu dans un journal** : un test lit le journal de tentative et la sortie `logcat` des essais
   instrumentés et n'y trouve ni la clé d'essai ni le texte des messages d'essai (T2, T12).
5. **Automatisation planifiée pendant que le serveur est hors ligne, que la clé a été retirée ou que le fournisseur a
   été supprimé** : l'exécution échoue proprement, est notée dans l'historique avec la raison, sans boucle de
   reprises ; la suppression d'un fournisseur annule ses travaux WorkManager (T8).

## Décisions du planificateur

Prises en l'absence de l'utilisateur ; chacune se change à faible coût si l'essai la contredit.

1. **Réseau, stockage et tâches en Kotlin, affichage en Flutter** : c'est l'architecture de toutes les phases ; la
   génération continue quand l'écran se ferme, comme les terminaux de la phase 13. *Coût si faux : un client Dart
   serait une réécriture de T2 et T6.*
2. **OkHttp et MockWebServer** plutôt que `HttpURLConnection` : annulation propre d'un flux, délais séparés, et
   MockWebServer demandé pour les tests. **Lecteur SSE maison** (`SseReader`, une centaine de lignes, testé) plutôt
   que `okhttp-sse` : contrôle des coupures et des erreurs en cours de flux. *Coût si faux : brancher `okhttp-sse`,
   une demi-tâche.*
3. **Room pour l'historique et les automatisations** (demandé) ; clés API **hors de Room**, scellées par la même
   `SecretBox` (Keystore) que les mots de passe des serveurs, plutôt qu'EncryptedSharedPreferences (déprécié) : un seul
   mécanisme de secrets dans Portail. Le contenu des conversations n'est pas chiffré en plus dans Room : stockage privé
   de l'application, chiffré par Android. *Coût si faux : sceller la colonne `content`, une tâche, sans recherche
   possible.*
4. **WorkManager** pour les automatisations planifiées (demandé) : survit aux redémarrages et respecte la batterie ;
   minimum 15 min imposé par Android. *Coût si faux : un service au premier plan pour des intervalles plus courts.*
5. **Rendu Markdown maison sur le paquet `markdown`** plutôt que `flutter_markdown` (abandonné par Flutter en 2025) :
   design system respecté, HTML jamais interprété, blocs de code copiables. *Coût si faux : `flutter_markdown_plus`,
   une tâche.*
6. **`/health` facultatif** : Ollama, vLLM et LocalAI ne l'ont pas tous ; l'état se déduit alors de `/v1/models`.
   *Coût si faux : aucun, le serveur maison l'a.*
7. **Pas d'embeddings à l'écran** en phase 15 : l'interface `AiProvider.embeddings` est prévue et testée contre le
   serveur d'essai, pour une recherche sémantique plus tard. *Coût si faux : un écran de plus.*
8. **Certificats auto-signés acceptés par empreinte** (T10, proposition) : un VPS sans nom de domaine n'a souvent pas
   de certificat reconnu ; même modèle de confiance que SSH. *Coût si faux : retirer T10, les serveurs à certificat
   reconnu marchent sans.*
9. **Pas de fichiers joints ni d'images** dans le chat en phase 15 : le contrat ne les prévoit pas encore. *Coût si
   faux : une phase ou une tâche après l'extension du contrat.*
